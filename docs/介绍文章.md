# ArcLog · 访迹：把 nginx 日志变成一张会飞的地图

> 一个纯前端的访问来源可视化工具：拖入 access.log，看你的访客从哪个城市"飞"到你的服务器。

## 为什么要做它

每个运维和后端工程师都干过这件事：

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head
```

统计出 Top 10 IP 之后呢？一串数字，毫无画面感。你想知道的是：

- 流量主要来自哪些省份？广东的访问是不是集中在深圳？
- 凌晨三点那波 404 扫描是从哪里打过来的？
- 昨天上线的新功能，哪些地区的用户先用了？

市面上的日志平台（ELK、SLS、各类商业 APM）当然能做到，但它们意味着：部署一套服务、上传日志数据、申请权限、忍受 license 到期。**有时候你只是想快速看一眼。**

ArcLog 的答案是：**打开网页，拖入日志文件，结束。**

## 它长什么样

拖入 `access.log` 后，你会看到一张中国地图：

- 每个有访问记录的城市射出一条**飞线**，箭头流向你的服务器位置；
- 线越粗、颜色越深（白→红渐变）、光晕越亮，代表流量越大——按排名分成 5 个等级，哪怕广东一家占了一半流量，其余省份依然层次分明；
- 来源城市有涟漪点呼吸闪烁；可疑来源会变成紫色警告；
- 底部时间轴可以**播放**一天内的流量演化，看着飞线随时间涨落。

侧栏是完整的统计面板：省份 Top 12、状态码彩签、运营商分布、客户端归类、路径 Top 10、可疑 IP 榜。所有板块与地图联动——点击「404」标签，地图立刻只显示产生 404 的那些飞线。

最后一键导出 PNG 快照或完整 HTML 报告发给同事。

## 技术上几个有意思的点

### 1. 自研 xdb 解析器，因为官方包进不了浏览器

IP → 省市定位用的是 [ip2region](https://github.com/lionsoul2014/ip2region)——国内精确率最高的离线 IP 库之一。但它的官方 npm 包依赖 Node 的 `fs` 模块，浏览器里跑不起来。

解法是把 xdb v2/v4 二进制格式自己实现一遍：256 字节头部 + 14 字节段索引 + 小端字节序的二分查找，130 行代码搞定，顺带做了完整的边界校验（数据库文件损坏时安全报错而不是抛 RangeError）。零依赖、完全离线。

### 2. 重活全在 Web Worker

MB 级的日志在主线程解析会让页面冻结几秒。ArcLog 把解析、IP 定位、聚合全部放进 Worker，主线程只负责渲染。切换过滤器时也不重新解析——Worker 缓存了解析结果和 IP 查询缓存，重算毫秒级完成。大文件解析时有实时进度条。

### 3. 流量分级用「排名」而非「数值」

最初版本按数值线性映射线宽，结果广东一家独大时其他省份全是细线没法看；换成对数映射又拉不开差距。最终采用 **quantile 分级**：按排名均分 5 档，每档固定粗细/颜色/光晕/股数。无论数据怎么分布，视觉层级永远清晰。

### 4. 飞线的抖动是确定性的

多股飞线需要起点抖动来避免重叠。如果用 `Math.random()`，每次过滤、切时间片都会让所有线束跳一次位置。改成对城市名做 hash 生成固定偏移——同一个城市的线束永远长一样。

### 5. 自定义格式不用写正则

nginx 允许自定义 `log_format`，字段顺序和内容千差万别。ArcLog 让用户直接粘贴 `log_format` 配置原文，程序把 `$remote_addr` 这类变量自动编译成命名捕获组正则，并用已加载的日志试跑匹配率校验（≥95% 绿灯），附上首行字段预览防止错位。

## 隐私是第一设计约束

整个应用没有任何网络请求（除了首次加载本地的 IP 数据库文件）。日志不上传、不落盘、不采集——关掉页面什么都不留。这也是它敢叫"本地分析工具"的底气。

适用场景包括但不限于：排查攻击来源前的快速侦察、给老板演示流量构成、个人博客主的周末分析、教学演示。

## 快速开始

```bash
git clone https://github.com/kevinvane/ArcLog.git
cd ArcLog
npm install
npm run dev
```

打开 `http://127.0.0.1:5173/`，等 IP 数据库加载完，拖入你的 `access.log`。

技术栈：Vue 3 + TypeScript + Vite + ECharts。更多实现细节见[方案总结](方案总结.md)与[自定义日志格式设计](自定义日志格式设计.md)。
