# ArcLog · 访迹 · 方案总结

本地分析 nginx 日志、在 2D 中国地图上以**飞线**展示访问 IP 来源（城市 → 固定服务器）的可视化工具。

- 仓库：<https://github.com/kevinvane/ArcLog>
- 技术栈：Vue 3 + TypeScript + Vite + ECharts 6 + vue-echarts
- 形态：纯前端单页应用，零后端、零外部请求，数据不出本机

## 1. 目标与约束

| 约束 | 决策 |
| --- | --- |
| 纯本地、隐私优先 | 纯前端，无后端；解析/定位/聚合全部在本机浏览器完成 |
| 前端技术栈 | Vue 3 + TypeScript + Vite |
| 日志规模 | MB ~ 百 MB 级（Web Worker 后台处理，不阻塞 UI） |
| IP 范围 | 以国内为主（ip2region），海外仅计数不绘线 |
| 飞线终点 | 固定的服务器位置（内置阿里云 12 地域下拉切换，支持 `lng,lat`） |

## 2. 技术选型与理由

- **可视化：ECharts + vue-echarts**
  - 原生支持 `geo` 地图 + `lines`（飞线特效）+ `effectScatter`（来源涟漪点），无需额外地图库。
- **IP 定位：ip2region xdb（自研解析器）**
  - 官方 `ip2region` npm 包依赖 Node `fs`，无法在浏览器运行。
  - 因此**自研纯 JS 的 xdb v4 读取器**（约 130 行）：256B Header + 14B 段索引二分查找，
    完全离线、零依赖，并带完整的头部/边界校验（损坏文件安全报错而非越界异常）。
  - 数据库文件 `public/data/ip2region.xdb`（约 11MB），由 Worker 自行 fetch 加载。
- **地图底图**：`china.json`（省级 GeoJSON，含省份中心点）；城市坐标表
  `china-cities.json` 来自阿里云 DataV 公开行政区划数据（363 个地级市）。
- **架构：计算全部下沉 Web Worker**
  - 解析、IP 定位、多维聚合都在 Worker 内完成；主线程只负责渲染与交互。
  - Worker 内缓存「已解析行 + IP 查询缓存」，过滤切换通过消息重算，秒级响应。

## 3. 数据流

```
access.log (拖拽/选择)
  └─ Worker: parseLog.ts       正则提取 IP / 状态码 / 路径 / 时间戳(分片+进度上报)
       └─ ip2region.ts         xdb 二分查找 → { country, province, city, isp }
            └─ analyze.ts      aggregateStats(lines, db, filters):
                 │               省份/城市聚合 · 状态码 · ISP · Top路径
                 │               可疑IP检测 · 异常省份预警 · 时间轴分桶
                 └─ postMessage(result) → 主线程
                      └─ App.vue ECharts geo + lines(飞线) + effectScatter(涟漪) + scatter(服务器)
```

消息协议：`load` → `dbReady/dbError`；`analyze(text, filters)` → `progress` → `result`；
`refilter(filters)` → `result`。postMessage 的 FIFO 特性保证结果不会乱序。

## 4. 关键实现点

### 4.1 xdb 解析器（`src/utils/ip2region.ts`）
- v4 格式：`256B Header`（@8/@12 为段索引起止指针）→ 段索引每块
  `14B = startIp(4) + endIp(4) + dataLen(2) + dataPtr(4)`。
- IP 在段索引中以**小端反序字节**存储，比较时按字节逆序比对（`cmpAt`）。
- 健壮性：构造时校验文件大小 ≥16B、指针范围与顺序；查找中对索引偏移和数据区
  做 `byteLength` 边界防护；`parseIP` 用严格正则拒绝畸形串。
- 性能：IP→归属 结果做缓存（上限 5 万条，超限清空，防扫描器场景内存膨胀）。

### 4.2 地理映射（`src/utils/geo.ts`）
- `PROVINCE_ALIAS`：ip2region 省份全名（`广东省`）→ GeoJSON 短名（`广东`）。
- `cityCenter`：363 城市坐标查询，兼容「南京/南京市」；直辖市等无条目自动回退省中心。
- `SERVER_REGIONS`：阿里云 12 地域（华北1青岛 ~ 西南1成都、中国香港）→ 城市坐标；
  `resolveServerLocation` 同时支持 `lng,lat` 直填。

### 4.3 飞线渲染（`src/App.vue`）
- **流量分级**：来源按数量排名 quantile 分成 5 级（任何分布下层级都清晰，
  不受"一家独大"影响）；级 → 线宽 `[9…1.6px]`、白→红颜色梯度、光晕强度。
- **密度控制**：稀疏/适中/密集三档，映射每级股数 `[2,1,1,1,1] / [4,2,1,1,1] / [6,4,3,2,1]`。
- **确定性抖动**：多股线起点偏移由城市名 hash 决定（非 Math.random），
  重算时线束位置稳定不跳变；不同弧度（curveness）形成扇形束。
- **回放模式**：`effect.period` 动态缩短至 0.85s（略短于 1s 时间片），保证箭头
  在切帧前飞完全程；总览模式保持 4.5s。
- 双向联动：悬停地图省份 ↔ 左侧榜单行互相高亮（`dispatchAction highlight/downplay`）。

### 4.4 聚合引擎（`src/utils/analyze.ts`）
- 单次遍历产出：省份/城市计数、状态码、ISP、Top 路径、可疑检测、时间轴。
- 过滤器（状态码 AND 省份 AND 运营商）在遍历中短路应用，所有视图口径一致。
- **可疑检测**：单 IP 请求数 ≥20 且错误率 ≥60%（扫描/爆破特征）；省份请求 ≥30
  且错误占比 ≥50% 触发预警（避免小样本误报）。阈值集中为常量可调。
- **时间轴**：预扫描确定时间范围；跨度 ≤72h 按小时、否则按天（上限 1500 桶）；
  日志过半无时间戳则停用时间轴。输出每城市的分时计数数组。

### 4.5 导出（`exportCsv` / `exportPng`）
- PNG：ECharts `getDataURL`（2x 像素密度 + 深色底色）。
- CSV：省份/城市/状态码/运营商/路径/可疑 IP 六段统计，带 UTF-8 BOM；
  对以 `= + - @ \t \r` 开头的单元格前置单引号，**防公式注入**（路径来自不可信日志）。

## 7. 已知限制

- GB 级超大日志建议先切分（当前为内存全量处理，百 MB 级体验良好；
  进一步优化可采用 Blob URL 流式读取）。
- 海外 IP 无城市级定位，如需全球视图需引入世界地图与 GeoLite2。
- 时间轴跨度超过约 4 年自动停用（桶数上限）。
- 日志格式仅适配 combined 及退化模式；自定义 format 待支持用户自定义正则。
