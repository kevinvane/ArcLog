# 优化路线图

按「价值 ÷ 工作量」排序的后续优化项。状态：⬜ 未开始 / 🔄 进行中 / ✅ 完成

## P0 快速见效（数据已就绪，仅补展示层）

### 1. Top 路径展示 ✅
- **现状**：`analyze.ts` 已计算 `topPaths`（Top 10 请求路径），但 UI 未显示。
- **方案**：侧栏「状态码」下方新增「路径 Top 10」列表，复用现有 `.list` 样式；长路径截断 + 悬停完整显示（`title` 属性或 tooltip）。
- **工作量**：约 20 分钟。

### 2. 运营商（ISP）维度 ✅
- **现状**：ip2region 已返回 `isp` 字段（阿里/腾讯/电信/联通/移动…），解析后丢弃未用。
- **方案**：
  - `analyze.ts` 聚合时增加 ISP 计数（`region.isp`，空值归为「未知」）；
  - 侧栏新增「运营商」分布（横向条形即可，不必引入饼图）；
  - 可选进阶：点击某 ISP 过滤飞线图。
- **价值**：快速识别云厂商/IDC 流量占比，爬虫与真实用户一目了然。
- **工作量**：约 1 小时。

## P1 体验升级

### 3. 时间轴回放 ✅
- **目标**：按小时/天播放访问动画，观察流量演化与攻击时段。
- **方案**：
  - 解析阶段保留每行时间戳（combined 格式自带），聚合为 `Map<小时, 省份计数>`；
  - 地图下方加播放条（ECharts 或自研 slider）：播放/暂停、速度、当前时段文本；
  - 播放时仅更新 series data，避免整图 setOption。
- **注意**：跨天日志先做「按时段聚合」而非逐帧；MB 级日志内存无压力。
- **工作量**：约 0.5~1 天。

### 4. 过滤联动 ✅
- **目标**：点状态码标签 / 省份行，只统计并绘制对应请求。
- **方案**：`analyze()` 返回原始明细索引（省份×状态码 的交叉计数），前端用 computed 做过滤重渲染，不重新解析文件。
- **依赖**：建议在 P0-2 之后做，过滤维度可复用同一套机制（状态码 / ISP / 省份）。
- **工作量**：约半天。

### 5. Web Worker 解析 ✅
- **现状**：主线程同步解析，百 MB 日志会卡 UI。
- **方案**：`parseLog + analyze` 移入 Worker（Vite 原生支持 `new Worker(new URL(...), {type:'module'})`）；xdb ArrayBuffer 可 transferable 传入；加进度条（按行数分片上报）。
- **触发条件**：单文件 > 50MB 再做，MB 级收益不明显。
- **工作量**：约半天。

## P2 功能拓展

### 6. 安全视角（可疑来源识别） ✅
- **目标**：自动识别扫描器/爆破行为。
- **方案**：
  - 维度：来源省份的 4xx+5xx 占比、单 IP 请求数、Top 路径中 404 集中度；
  - 命中的省份/IP 列表标红置顶，地图上对应飞线改用警示色（如紫红）；
  - 输出「Top 可疑 IP」表格（IP、请求数、404 数、命中路径）。
- **工作量**：1 天左右。

### 7. 城市级飞线 ✅
- **现状**：飞线起点是省级中心点，省内所有 IP 视觉上同一点出发。
- **方案**：引入中国城市坐标表（约 340 城市 JSON，可由 ip2region 返回的 city 名匹配）；匹配失败回退省中心。
- **注意**：城市点多后需控制飞线股数策略，避免视觉爆炸。
- **工作量**：半天 ~ 1 天。

### 8. 导出报告 ✅（PNG + CSV + 单文件 HTML 报告已实现）
- **方案 A**：ECharts 自带 `getDataURL` 导出 PNG（含统计面板需自行拼装 canvas 或 html2canvas）。
- **方案 B**：生成独立单文件 HTML 报告（内联数据 + 图表配置），可直接发给同事。
- **工作量**：A 约 1 小时；B 约半天。
